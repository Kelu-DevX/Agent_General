7B Winter Pilot Implementation Plan
   For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
   (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
   checkbox ( - [ ] ) syntax for tracking.

Goal: Ship the 7B winter pilot — a mobile-first Sandpoint handbook site with the "Postcards" 5-objective
photo game — on Cloudflare's free tier.

Architecture: One Cloudflare Worker (Hono + Hono JSX server-rendered pages, small amount of client
JS), D1 (SQLite) for data, R2 for photos. Points are a ledger (grants/revocations), totals computed. All
moderation flows through an admin approval queue.

Tech Stack: TypeScript, Hono (with JSX), Cloudflare Workers + D1 + R2, Wrangler, Vitest with
@cloudflare/vitest-pool-workers . No other runtime dependencies without need.

Spec: docs/design.md



Global Constraints

   Hosting cost: $0/month. Free tiers only (Workers, D1, R2). No paid APIs, no email service.

   Brand copy: site is "7B", game is "Postcards", points are "stamps". Warm, wholesome, postcard-
   vintage tone; never corporate, never kids'-toy.

   Domain is config ( SITE_URL var); everything runs on the temporary *.workers.dev URL until Luke
   buys the7b.me.

   Privacy: public pages show display names only — never emails, never location. Photos must carry
   no EXIF/GPS when stored.

   Uploads: JPEG only, max 2,500,000 bytes, max 20 uploads per user per day.

   Signup requires two checkboxes: age 13+ / photo-rights acknowledgment (combined into terms
   agreement) and an optional mailing-list consent checkbox (unchecked by default).

   Season: submissions accepted through 2027-03-31 (config SEASON_END ).

   Mobile-first: every page usable on a ~380px viewport; admin fully operable from a phone.

   Nothing deploys live without Luke's explicit go-ahead (deploy is a checklist item, not a task step).



Review Focus

   Duplicate email or display name at signup → friendly inline error, not a 500. (Test added to Task 4.)

   Non-JPEG or >2.5MB upload sent directly to the API (bypassing client JS) → rejected with a clear
   message, nothing written to R2. (Test in Task 6.)
    JPEG with EXIF/GPS uploaded directly to the API → stored object has EXIF segments stripped.
    (Test in Task 6.)

    Approve called twice on one submission, or remove after approve → points granted at most once,
    removal revokes exactly once; no double-count. (Tests in Task 7.)

    Logged-out user POSTs a submission or opens /admin ; non-admin opens /admin → redirect to
    login / 403, never a crash or silent success. (Tests in Tasks 6–7.)
